*Цели проекта*

Главная цель — настроить простой и понятный CI/CD pipeline, который будет автоматически выполнять нужные действия при изменениях в репозитории.
Этапы работы pipeline:
Триггер — событие, которое запускает процесс.
Скачивание кода — GitHub берёт свежие файлы из репозитория.
Установка зависимостей — чтобы проект мог собраться.
Запуск тестов — проверка, что код не сломан.
Сборка — создание итогового билда.
Развёртывание (по желанию) — загрузка результата на сервер.
| № | Этап     | Что делает                 | Когда запускается                  |
| - | -------- | -------------------------- | ---------------------------------- |
| 1 | Триггер  | Запускает pipeline         | При push или pull request в `main` |
| 2 | Checkout | Скачивает код              | Сразу после триггера               |
| 3 | Install  | Устанавливает зависимости  | После скачивания                   |
| 4 | Test     | Запускает тесты            | После установки зависимостей       |
| 5 | Build    | Собирает проект            | Если тесты успешны                 |
| 6 | Deploy   | Развёртывает (опционально) | Если сборка успешная               |
name: My CI/CD

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  build_and_test:
    runs-on: ubuntu-latest

    steps:
      - name: Скачать код
        uses: actions/checkout@v3

      - name: Установить зависимости
        run: npm install

      - name: Запустить тесты
        run: npm test

      - name: Сборка проекта
        run: npm run build
*Что делает мой CI/CD*
Когда я отправляю изменения в ветку main, GitHub автоматически:  -скачивает мой код
  -устанавливает зависимости
  -запускает тесты
  -собирает проект
  Если тесты падают — билд останавливается.
